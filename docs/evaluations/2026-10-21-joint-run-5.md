## 这一轮暴露并修掉的问题

百炼当晚不稳定（两段各一小时内 TCP 连接超时、单轮 60–70 秒），把几处"等不起"的地方全照出来了：

1. **分诊 25 秒超时直接丢消息**，而且 SDK 把中止抛成普通 `Error`，被记成 `provider_error` 不重试。改为超时/供应商错误也重试一次、窗口 40 秒、记录原因。
2. **研究期中止不走"用已有证据作答"**：同样是 `Error("Request was aborted.")` 没被识别成超时。按名字和消息里的 abort/timeout 识别。
3. **任务规划一次中止就永久丢掉求助**：小林的打印机首问 45 秒规划调用被中止，之后他说什么都是"没有任务的续问"。规划调用对中止重试一次，并记录原因。
4. **没有任务的歧义续问在群里反问**：小林回小陆"能连最好啦 不能也行"，分诊判续问，规划判歧义，模型在群里发"想确认一下你要我往哪边走……"。没有对 A2H 说话的歧义续问现在直接不作声。
5. **最终作答 45 秒不够**：第一稿就要 26–38 秒，退回一次再修就被中止，娜娜买药首问和小周带娃都这样丢了。整条消息 150 → 210 秒，作答窗口 45 → 75 秒，作答证据包 24000 → 16000 字符。
6. **"条件没变"的再问被当成已处理**：第一次打印机求助从未开出任务，再问一遍被判 `no_new_condition` 丢弃。现在再问时查不到该成员的未结任务，就按新求助处理（`reask_without_task`）。
7. **金额千分位**："£1,230/月"被读成 £1，两条超预算的房间通过了预算校验，链接标题显示"£1/月"。
8. 演员侧：模型端点 5 秒连接超时太紧（首刻就挂）；8 人生活复盘输出超过 4096 完成 token 被截断导致 JSON 无效（两次）；投递未知的消息需要操作者明确接受才能继续。分别改为 15 秒、8192、`--accept-uncertain`。

## 仍待处理

- 二手市场与信息类求助每条仍 5.5–8.2 万 token，研究期几乎总是撞累计输入上限后才作答；下一步应把"搜索 → 补读 → 记录候选"压成更少轮次。
- `page_read: non_public_destination` 每条求助出现 1–2 次，是浪费的轮次；应把这类站点从可读列表里提前排除。
- 合租回复选到的两条都超预算或未标价，而 A2H 当时有 £870 的 zone 3 东边单间；候选排序对"未知价格"过于宽容。
- 群回复虽然分成了"一句话 + 证据卡"，证据卡仍常到 600 字。
