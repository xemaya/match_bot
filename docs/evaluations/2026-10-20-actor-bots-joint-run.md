# actor_bots 联合真实回归：Match Bot 观察

2026-10-20。用户批准 Match Bot 最多 50 万生成 token。8 个 actor_bots 演员在专用群 `-5013792100`（A2H 演员世界 · 8人演化 1020）里模拟伦敦留学生生活群，本地 Match Bot 以 Phase 2、`OUTBOUND_UNSURE_ACTION=drop`、`JEV_POLICY=strict` 运行；生成用百炼 Token Plan `deepseek-v4.1-flash-1017`（reasoning low），联网搜索用 DeepSeek 官方，`XHS_RESEARCH_ENABLED=false`。白名单只含该群和 8 个演员 Bot。外部看门脚本在观测到 50 万生成 token 时停用该群并停掉 bot / worker。完整数据见 actor_bots 的 `docs/student-chat-match-live-20261020.{md,json}`。

## 结果

28 条演员消息：

| 结局 | 条数 | 生成 token |
| --- | ---: | ---: |
| 有真实回复 | 9 | 约 23.5 万 |
| 做了研究但没有回复 | 3 | 28.5 万 |
| Jev 暂时不可用，被丢弃（failed） | 5 | 0 |
| 按规则不回（广告 / 供给） | 4 | 0 |
| 预算停止时仍在排队 | 7 | 0 |

约 15 分钟用完 50 万 token。真正有用的回复有 3 条：狗岛药房（具体药房、地址和营业时间）、A2H 市场上 £20 的无线打印机（并提醒在 SE1，不在 Mile End）、确认需求条件。

## 问题（按影响排序）

1. **研究了却不回复，最费钱。** 娜娜补充的一句症状说明（“就是普通感冒 鼻子堵嗓子疼那种”）花了 8.9 万；小林回复别人的一句（“se1也太远了……再蹲蹲mile end附近的吧”）花了 11.2 万；雯雯补充的一句地点说明（“我住Liverpool Street这边……”）花了 8.4 万。三条都没有发出任何回复。对同一用户的补充或接话，应该先判断是不是已有请求的追加条件，再决定要不要重新研究，而且研究要有预算上限。
2. **看不到群聊上下文，介入了别人之间的对话。** 小陆回复小周“5岁可以的 名额给你留一个”，Match Bot 插话说“这句话看起来是对方在回复你……是哪家机构？”；小鱼回复阿明“11月15号我这边有点晚”，Match Bot 连发两条长消息追问“你说的11月15号是哪个房子”。入站 Jev 只看发送者本人最近 5 条消息，看不到群里其他人刚说了什么。这和 2026-10-19 review 的发现一致，这次有了真实证据。
3. **群内同伴撮合没有发生。** 阿明发的“Stratford合租空出来一间 950含bill 11月15号起”被 P16 当作纯广告丢掉（`dropped_by_jev`），没有记录为同伴供给。所以小鱼求合租时，Match Bot 回的是“这次查询没能完成”，而不是“群里阿明刚好有一间”。担心 worker 写死 `answerRequests: true` 后 `upsert_supply` 不可用、`Supply` 表也没有物品描述，这一点在本轮得到了证实。
4. **Jev 暂时不可用就直接丢掉真实求助。** 小林的 GP 注册问题、娜娜找人喂猫、小周报名活动，都因为 Jev `http_error` 被标记为 failed，没有重试。与此同时演员宿主在用同一个 Jev key，存在并发争用。按 AGENTS.md，Jev 不可用时“不进 agent”是有意为之；但对明显是求助的消息，可以考虑延迟重试一次，而不是直接放弃。
5. **对同一个人连发的两条分别处理。** 小鱼的“求助!!……”和紧跟着的“短租快到期了 有点慌 谢谢大家”分别得到两条一样的失败回复。连发的短消息应该合并处理。
6. **失败的回复没有信息量。** “这次查询没能完成，还不能判断有没有合适的。”“我查到了一些线索，但这次没能整理成可靠的答复。”对用户没有帮助，也不说明下一步。没把握时，宁可不发或者给一个具体的方向。
7. **回复太长。** 药房那条约 600 字，在群聊里不像人话；关键信息一两行就够了，详细内容可以放到后续追问里。

## 本轮没有改 match_bot 代码

上面的问题都涉及产品取舍：P16 广告策略、入站给 Jev 的上下文、研究预算、同伴供给的数据结构。需要先确认方向再动手。演员联合测试的环境和步骤见 `docs/testing/actor-bots.md`。
