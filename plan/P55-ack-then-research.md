# P55 先回一句再查

状态：待评审（2026-10-22 起草）；阶段 B 涉及 AGENTS.md §3.3 第 10 条，需用户拍板 D1–D2。负责人 claude。依赖：阶段 A 只依赖 P52（可与 P53 并行）；阶段 B 依赖 P53（主 agent 决定是否研究、新鲜度检查）。范围 阶段 A：`packages/agent`（主 agent 调研究前的表情确认）；阶段 B：`packages/queue`、`apps/worker`（后台研究任务与回推）、`packages/agent`。

总体路线见 [P52](./P52-researcher-subagent-single-voice.md#总体路线p52p55)。

## 为什么

第七轮每条进 agent 的消息从入站到出站中位数 35 秒，最长 139 秒，期间群里看不到 A2H 有任何反应。真人被问到要查一下的事，会先"我看看"或点个表情，查到了再回；不会沉默半分钟后突然贴一条完整结果。

另一个问题是并发：入站 lease 按用户串行，研究期间同一成员补充的条件被 `deferMs` 推迟，处理完上一条再处理这一条，于是同一条线上 A2H 连发（0.34.0 的 5 分钟冷却就是为此打的补丁）。

业界参照：OpenClaw `sessions_spawn` 立即返回、子 agent 完成后以消息形式推回（`sessions_yield`），文档特别提醒"沉默结束前先发确认"；HUMA 在生成期间收到新消息会从路由重新开始。

## 分两段

### 阶段 A：表情确认（不改契约）

消息 `addressedToBot`（@ A2H 或回复 A2H）且 triage 放行为 `answer` / `continue` 时，代码在 planner 之前就给原消息点一个表情（👀）。放在 triage 之后而不是主 agent 决定研究之后，是因为 planner + 主 agent 第一步还要两次模型调用，等到那时已经十几秒。表情反应（`kind=reaction`）按 AGENTS.md §3.3 第 3 条本来就不送审、不调 Jev、不占频控，Phase 0 只记录。

- 👀 由代码点，不加进模型可选的 `REACTION_EMOJI`（现为 👍 🙏 ❤ 👌）。
- 本条最终没有任何文字出站（主 agent 沉默、研究失败）时撤掉表情：sender 现在只会设置表情（`sender.ts` `setMessageReaction`），要新增"清除反应"（空数组）这一出站形态；主 agent 若选择用另一个表情收尾，则直接替换。
- 不对非直接提问点表情（不想让群友觉得被盯着）。

### 阶段 B：后台研究与回推（改契约，需拍板）

1. 主 agent 调 `research` 不再同步等待：代码把研究员作为 BullMQ 任务 `research_task`（载荷：taskId、objective、focus、ctx 的加密检查点）入队后，主 agent 本轮结束；可以同时 `say_briefly` 一句确认（D1）。
2. 研究员跑完写证据与 `finish_research` 结论到任务账本，入队 `resume_main`；worker 以"研究结果到了"为输入重新跑一次主 agent（带最新群视图——期间的群消息、提问者补充的条件都在里面），由它决定回答、改问、或因为已经有人答了而沉默。
3. 研究期间同一成员的新消息不再被 `deferMs` 推迟到研究结束：主 agent 正常处理；若是补充条件，把它追加到进行中的 `research_task`（下一轮研究读到），并可只回表情。
4. 每个请求的出站上限从"最多一条状态"变为"最多一条确认 + 一条答复"（D2）；确认句由代码从固定变体里选、不含实体 / 数字 / 链接，复用 `reply_request_status` 的放行规则。

## 需要用户拍板

- **D1 确认用表情还是一句话。** 推荐先只做阶段 A（表情），用联合实测看效果；文字确认（"我看看哈"一类）在阶段 B 再定。
- **D2 修改 AGENTS.md §3.3 第 10 条**：允许一个请求有一条代码固定的确认 + 一条答复。只在做阶段 B 时需要。

## 验收标准

阶段 A：
1. 直接提问的 `firstSignalMs` 中位数 ≤ 8 s（基线即答复时间，约 35 s）。
2. 点了 👀 却最终沉默的，表情 100% 被撤回。

阶段 B：
1. 研究期间提问者补充的条件被同一次研究吸收，同一条线上 A2H 的发言数 ≤ 2（确认 + 答复）。
2. 研究期间他人已答 → 不再答复（新鲜度检查生效），有测试与联合实测案例。
3. 回推幂等：重复的 `resume_main` 不产生重复出站。
4. `pnpm check` 全绿（db 基线除外）。

## 额度

阶段 A 几乎不增加生成 token。阶段 B 每次回推多一次主 agent 调用（约 1 万 token）；联合实测另批。
