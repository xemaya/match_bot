# P49 证据卡改为例外：去标签、去来源行、群记录只喂那句话

状态：评审中（代码、测试、文档在工作树完成，未提交）。负责人 claude。依赖：P48（0.32.0 工作树，未提交）。范围 `packages/agent`、`packages/domain`、`packages/channel-telegram`，不动提示词目录结构。

用户决定（2026-10-21）：P48 联合实测后，用词有好转，但每条回复固化为"一段像人的话 + 一段详情 + 一段来源"，比以前更机械。按诊断方向开 P49。

## 诊断（2026-10-21 实测 4 条新版推荐）

| 条        | 那句话 | details  | 来源行        | 总长 |
| --------- | -----: | -------: | ------------- | ---: |
| 房源      |    118 |   约 330 | 2 行          |  919 |
| Young V&A |    142 |   约 400 | 1 行 5 个链接 | 1083 |
| 打印机    |    108 |   约 300 | 2 行          |  877 |

- 渲染器是确定性的：有 details 或来源就拼成"那句话 + 【详情】 + details + 来源"；事实型回答 refs 必填，所以每条必出卡。
- details 名义可选，但 chat-line.md、工具参数说明、收尾协议三处都在催它填；研究阶段永远找得到比 150 字多的东西，于是 details 成了"正文"，那句话成了"摘要"。
- 【详情】加粗是表单字段名；来源行带编号，标题是抓来的页面 title（出现过 HTML 残片）；市场场景每个候选各一行"来源："。
- 群记录把 Match Bot 自己的消息（含卡的开头）喂回模型，模板自我强化。
- 根子上仍只有"交付报告"一种发言动作，本包不解决，见"不在本包"。

## 目标

卡是例外，不是默认。多数群回复只有那句话；卡只在真有第二个选项、口径冲突或一条必须核实的条件时出现，且短；来源链接不再单独成行、不带标签和编号；Telegram 折叠块本身就是视觉提示，不再有【详情】标题；模型回看群记录时只看到自己说的那句话。

## 验收标准

1. 落库文本：只有那句话时就是那句话；有卡时为"那句话 + 空行 + U+2063 行 + 卡"，卡内没有"【详情】"、"来源："、"1. "编号。
2. Telegram 发出的正文不含 U+2063，卡折叠为 `expandable_blockquote`，卡内链接可点；无卡不折叠。
3. `details` 超过 300 字被退回，反馈先说改法。
4. 群记录里 Match Bot 自己的行不含卡内容。
5. 收尾协议与 DELIVERY 规则中没有要求每条回复都覆盖互补证据或披露未查条件的句子；FACT 规则"只披露影响决定的不确定"保留。
6. 三处预算不高于 P37；`pnpm check` 与 prompt-audit 通过；评测回放 precision / recall 不低于 P48。
7. 不新增模型调用、出站路径、个人数据字段；不改 Jev、审批、频控、Phase 门。

## 不在本包

- 新增发言动作（先回一句再查、点名转介）：需要新的入站/出站路径。
- 把链接挂在那句话里提到的店名上：需要模型标注锚点或可靠的名称匹配，先看本包效果。
- 群记录保留显示名。
